# 策略与规则

**这份文档以代码为准**，改代码就要改它——`tests/test_docs_consistency.py` 断言下面的技术分量权重表与 `analysis/technical.py::SIGNAL_COMPONENT_WEIGHTS` 逐项一致。

参数值的唯一出处是 `config/settings.py`（除技术分量权重在 `analysis/technical.py`）。这里写的是**口径与判定规则**。

## 信号是"单源选择 + 阈值"，不是多源融合

`strategy/decision.py::decide` 做的事：从三个信号源里**选一个**（`technical` / `chanlun` / `kronos`，默认 `DEFAULT_SIGNAL_SOURCE = technical`），拿它的信号值与阈值比：

- `信号值 ≥ buy_threshold` → 买入
- `信号值 ≤ sell_threshold`（默认 `-buy_threshold`，对称）→ 卖出
- 之间 → 观望

阈值默认 `SIGNAL_THRESHOLD = 0.3`，页面上可临时改。**没有"技术×w1 + 缠论×w2"这种多源加权**——这个模块以前的名字曾暗示有，issue #41 把名字改成了与行为一致的 `decision.py`。

各源计算一天信号需要的前置 K 线天数在 `SIGNAL_LOOKBACK`：技术 150、缠论 150、Kronos 400（MACD 的 slow EMA 要约 80 根才收敛，天数不够会误报金叉）。

## 技术信号（7 个分量加权 × 成交量确认）

`analysis/technical.py`。各分量给 −1~+1 的信号，按权重求和：

| 分量 | 权重 | 买入 | 卖出 |
|---|---|---|---|
| supertrend | 0.23 | 转多 | 转空 |
| macd | 0.20 | DIF 上穿 DEA（金叉） | DIF 下穿 DEA（死叉） |
| boll | 0.15 | 触及下轨反弹 | 触及上轨回落 |
| kdj | 0.12 | K 上穿 D（J<20 加强） | K 下穿 D（J>80 加强） |
| ma_cross | 0.12 | MA5 上穿 MA20 | MA5 下穿 MA20 |
| ma_trend | 0.10 | 多头排列（短>中>长） | 空头排列（短<中<长） |
| rsi | 0.08 | 从超卖回升（上穿 30） | 从超买回落（下穿 70） |

加权和再乘**成交量确认系数**：量比 > 1.5 → ×1.5，> 2.0 → ×1.8，< 0.5 → ×0.5，其余 ×1.0。

指标周期在 `settings.TECHNICAL`（MA 5/10/20/60、MACD 12/26/9、RSI 14、KDJ 9、布林 20、SuperTrend ATR 10 × 3.0）。

## 缠论信号

`analysis/chanlun.py`，基于 czsc 识别分型/笔/中枢，三类买卖点给固定强度：

| 买卖点 | 强度 | 含义 |
|---|---|---|
| B1 / S1 | ±1.0 | 趋势背驰（反转） |
| B3 / S3 | ±0.8 | 中枢突破回踩（趋势加速） |
| B2 / S2 | ±0.7 | 回调不破前低/高（趋势确认） |

## Kronos 预测

`analysis/kronos_pred.py`，基础模型对未来若干根 K 线采样，转成 −1~+1 的信号（饱和点 `KRONOS_SATURATE_PCT = 0.08`，即预测涨跌 8% 视为满格）。

**单只在 CPU 上约 40 秒**，所以：只在单股票页手动触发；不进总览页扫描、不进板块选股（`PICK_SIGNALS` 写死不含它）、不进对话工具集。模型权重与第三方仓库不入 git（见 `.gitignore`）。

## 仓位管理（可插拔）

`strategy/trade_strategy.py`。内置两个，`strategy/custom/*.py` 里的自动发现：

**默认强度分档（`default`）**：出现买入信号时按信号强度分三档下单——`|强度| ≥ 0.7` 重仓、`≥ 0.3` 标准仓、其余轻仓，对应仓位比例见 `settings.POSITION_SIZING`（30% / 20% / 10%）；卖出信号清仓。

**装死四分之一（`playdead_quarter`）**：仓位只有 0/25/50/75/100% 五档，维护买入价栈（LIFO）——当前价 ≤ 栈顶买入价×(1−加仓阈值) 就加 25%；当前价 ≥ 栈内均价×(1+减仓阈值) 就减 25%。两个阈值默认各 10%，页面可调。

自定义策略的参数由 `PARAMS` 元数据声明，界面按元数据自动渲染输入框，不需要改 UI 代码。

## 回测规则

`backtest/`。A 股与港股两套参数（`settings.BACKTEST` / `BACKTEST_HK`）：

| | A 股 | 港股 |
|---|---|---|
| T+N | T+1（当日买入不可卖） | T+0 |
| 涨跌停 | 主板 ±10%、创业板/科创板 ±20%（`LIMIT_RULES`） | 不限（按 20% 兜底） |
| 佣金 | 万 2.5 | 万 5，最低 50 港元 |
| 印花税 | 千 1（卖出单边） | 千 1.3（双边） |
| 滑点 | 0.2% | 0.2% |
| 单只最大仓位 | 30% | 30% |
| 最小交易单位 | 100 股（指数按点位，1 为单位） | 每手 100 股（实际每只不同） |

具体数值改 `config/settings.py`，这里只列口径。

## 板块热度分（轮动页）

`analysis/rotation.py`：

```
热度分 = w_excess · z(20日超额收益) + w_net · z(20日资金净额)
```

两项都在**池内**做 z-score（样本标准差 ddof=1；有效值 < 2 个或标准差为 0 时该项给 0——此时无区分度，不该左右排序；缺失值保持 None，不当 0）。权重在 `settings.SECTOR_HOTNESS_WEIGHTS`，运行时读取，改了下次计算即生效。

轮动标签由**排名迁移**判定（阈值是"池内 1/3 的名次数"，边界一律达到即触发）：

| 标签 | 判定 |
|---|---|
| 持续走强 | 短窗、长窗超额均 > 0 且长窗排名在池内前 1/3 |
| 新晋走强 | 短窗排名比长窗上升 ≥ 池内 1/3 名次，且短窗超额 > 0 |
| 转弱 | 短窗排名比长窗下降 ≥ 池内 1/3 名次，或长窗超额 > 0 而短窗已转负 |
| 持续弱势 | 短窗、长窗超额均 < 0 |

一个板块只出一个标签（优先级即上表顺序）；指标缺失的板块不猜标签。

## 板块内选股排序分

`analysis/sector_pick.py`：

```
排序分 = w_tech · z(技术信号) + w_excess · z(相对板块超额收益) + w_fund · 基本面加减分
```

- 前两项在**候选集内**做 z-score（与热度分同一套 z-score 实现）；
- 基本面加减分 = flags 的正负标签各 ±0.5 累加，映射表写死在 `_FLAG_RULES`；认不出的标签按 0 计并在该行标注；
- 权重在 `settings.SECTOR_PICK_WEIGHTS`；细算只数在 `SECTOR_PICK_TOP_N`（默认 20）；
- **缠论信号照算照显示但不进排序分**——它是给人看的旁证，不是权重项；
- 相对板块超额 = 个股 N 日累计收益 − 该板块指数同期累计收益（N = 20 交易日）；板块指数取不到时该项按 0 计并标注。

## 情绪与基本面：不进信号系统

新闻情绪分（`analysis/sentiment.py`）与基本面 flags（`analysis/fundamental.py`）**不产生信号、不进 `decision`、不影响回测与仓位**。它们只出现在页面卡片、板块选股的排序分（基本面项）、以及对话工具里。`SIGNAL_SOURCES` / `SOURCE_COLUMNS` 里不含它们，有测试守着这条边界。
